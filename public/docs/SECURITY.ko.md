# 보안

> **번역 안내.** 이 문서는 기계 번역되었으며 원어민 검수를 거치지 않았습니다. 기준이 되는 것은 영어판이며, 내용이 다를 경우 영어 원문이 우선합니다. 가장 정확하고 최신인 표현은 영어 문서를 참고하시기 바랍니다.

BugIt QA Agent는 사람이 판단에 참여하는(human in the loop) 어시스턴트입니다. 사용자의 VS Code 세션과 사용자가 활성화한 연동을 통해서만 동작합니다.

## BugIt의 보호 방식
- **확인 없이는 쓰지 않습니다.** 보고서를 담은 생성, 댓글, 첨부, 알림은 모두 미리 보기로 먼저 표시되며, 되돌릴 수 없는 제출은 FILE IT을 직접 입력해야 합니다. 채팅 텍스트만으로는 절대 제출되지 않으며, 단순한 "네"로는 충분하지 않습니다. 예외가 하나 있습니다. `notify connect`, `notify test` 또는 `notify doctor --live`로 직접 시작한 연결 테스트는 미리 보기 없이 고정된 테스트 메시지 하나를 보냅니다. 지정한 채널로 보내며, 지정하지 않았다면 켜 둔 모든 채널로 보냅니다. 이 메시지에는 보고서 내용이 포함되지 않으며, dry run이 이를 차단합니다.
- **Dry run = 작업이 이루어지는 모든 곳에서 읽기 전용.** `QA_AGENT_DRY_RUN=1`은 BugIt이 추적 시스템에 쓰는 것도, 추적 시스템에서 읽는 것도 막습니다. 티켓, 댓글, 첨부, 알림이 전혀 없고, 저장된 자격 증명도 잠금 해제되지 않습니다. 예외가 하나 있으며, 이는 사용자 데이터가 아니라 BugIt 자체에 관한 것입니다. 이 설치본의 라이선스 인증이나 업데이트를 위해 의도적으로 실행하는 명령은 여전히 BugIt 자체 라이선스 서버에 연결되고, `tools/update.py`는 가져온 서명된 릴리스를 여전히 설치합니다. 셸에 이 변수가 영구적으로 설정된 컴퓨터도 보안 수정을 받을 수 있어야 하기 때문입니다. 채팅에서 "dry run"이라고 말하면 어시스턴트에게 실행을 보류해 달라고 요청하는 것이며, 유용하지만 같은 보장은 아닙니다. 코드가 강제하는 모드를 설정하는 것은 환경 변수뿐입니다.
- **파일에 비밀 정보를 두지 않습니다.** `config.json`에는 조직과 URL만 들어 있고, 토큰은 OS 자격 증명 저장소에 보관됩니다. 검사기는 비밀 정보처럼 보이는 모든 것을 표시합니다. `redact.py`는 초안에서 이메일, 토큰, IP 주소를 최대한 제거합니다.
- **기본값은 꺼짐입니다.** 모든 연동은 비활성화된 상태로 제공되며, 사용자가 선택하기 전에는 아무것도 연결하거나 제출하지 않습니다.
- **출력은 데이터입니다.** 페이지, 티켓, 크래시 텍스트는 명령이 아니라 데이터로 취급되므로, 주입된 지시는 표시되어 드러날 뿐 실행되지 않습니다.

## 알려진 제한 사항
- 쓰기 차단은 OS가 아니라 에이전트가 강제합니다. 환경 변수가 확실히 중단시키는 것은 함께 제공되는 Python 도우미뿐입니다. 신뢰할 수 있는 런타임에서 실행하세요.
- 에이전트는 연결한 모든 것에 접근할 수 있으며, 자격 증명의 권한 범위 = 피해 범위입니다. **최소 권한** 토큰을 사용하세요.
- 대부분의 추적 시스템은 이슈를 실제로 삭제할 수 없으므로, 그곳에서 "실행 취소"는 설계상 제한됩니다.

## 보안 강화 체크리스트
1. 추적 시스템마다 최소 권한의 전용 서비스 계정을 사용하세요.
2. 토큰은 OS 저장소에 보관하고, 절대 `config.json`에 붙여 넣지 마세요.
3. 설정 후 `python tools/validate_config.py`를 실행해 유출과 잘못된 설정을 찾아내세요.
4. 사용하는 MCP 서버만 시작하고, 나머지는 중지하세요.
