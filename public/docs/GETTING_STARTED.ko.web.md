# BugIt 시작하기

> **번역 안내.** 이 문서는 기계 번역되었으며 원어민 검수를 거치지 않았습니다. 기준이 되는 것은 영어판이며, 내용이 다를 경우 영어 원문이 우선합니다. 가장 정확하고 최신인 표현은 영어 문서를 참고하시기 바랍니다.

BugIt는 대략적인 테스트 메모를 VS Code 안에서 검토된 버그 리포트로 바꿔 줍니다. VS Code와 GitHub Copilot이 설치된 Windows 11이 릴리스 검증을 마친 클라이언트 환경입니다.

## 시작하기 전에

- 최신 VS Code를 설치하고 GitHub Copilot에 로그인합니다.
- 릴리스 검증을 마친 Python 3.10부터 3.13까지의 인터프리터를 설치합니다.
- 계정 대시보드에서 BugIt를 다운로드하고 로컬 폴더에 압축을 풉니다.
- 토큰, 고객 데이터, 비공개 소스 코드는 채팅과 구성 파일에 포함하지 마세요.

## 활성화 및 구성

- 압축을 푼 BugIt 폴더를 신뢰할 수 있는 VS Code 작업 공간으로 엽니다.
- Copilot Chat에서 BugIt QA Agent를 선택하고 `Activate`를 입력합니다(계정에 둘 다 있는 경우 `--solo` 또는 `--team`을 붙입니다).
- BugIt가 브라우저에서 BugIt 포털을 엽니다. 본인의 BugIt 계정으로 로그인하세요. 비밀번호는 브라우저에만 머무르며 VS Code에는 입력되지 않습니다.
- 이 컴퓨터에서 사용할 Solo 또는 Team 권한을 선택한 다음 이 기기를 검토하고 승인합니다.
- VS Code로 돌아옵니다. BugIt가 자동으로 인증을 완료합니다. 복사, 붙여넣기, 표시할 라이선스 키가 없습니다.
- `Begin setup`을 입력하고 팀이 사용하는 통합만 선택합니다.
- 버그 추적 시스템을 한 번 연결합니다: `python tools/connect.py jira` (`ado`, `github`, `gitlab`, `linear`, `clickup`, `asana`, `trello`, `shortcut`, `youtrack`, `bugzilla`도 가능). 토큰은 본인 계정에서 만들어 가려진 로컬 입력창에 붙여 넣습니다. 토큰은 운영체제의 자격 증명 저장소에 저장되며 파일에는 남지 않습니다.
- 티켓을 생성하기 전에 BugIt가 선택한 서비스와 프로젝트를 검증하도록 합니다.

## 액세스 관리

- 하나의 설치에서는 한 번에 하나의 활성 권한만 사용합니다. 이 컴퓨터를 다른 Solo 또는 Team 권한으로 옮기려면 `Switch license`를 입력하고 브라우저에서 다시 승인하세요. 취소하면 현재 권한이 그대로 유지됩니다.
- `Deactivate`는 이 컴퓨터에서만 권한을 제거합니다. 좌석, 기기, 멤버십, 역할, 청구는 VS Code가 아니라 포털에서 관리합니다.
- Team 액세스는 사람별입니다. 각 구성원은 자신의 BugIt 계정과 활성 멤버십으로 로그인합니다. 공유 키나 공유 로그인은 없습니다.
- 온라인 확인에 성공하면 BugIt는 Solo와 Team 모두 최대 72시간 동안 오프라인으로 계속 작동하고, 다시 연결되면 즉시 최신 포털 상태를 적용합니다.
- 업데이트는 서명된 권한으로 인증되므로 새 빌드를 다운로드할 때 키를 요구하지 않습니다.

## 연결 상태

- BugIt은 열한 개 추적 시스템에 각각의 REST API로, 사용자가 자신의 계정에서 만든 자격 증명을 사용해 등록합니다: Jira Cloud, Azure DevOps, GitHub Issues, GitLab Issues, Bugzilla, YouTrack, Linear, Shortcut, ClickUp, Asana, Trello. 설정은 사용자가 의존하기 전에 연결을 검증합니다.
- Confluence Cloud는 안내형 Atlassian Rovo MCP 경로(브라우저 로그인)로 지식 소스로 연결됩니다. Sentry와 Notion은 서비스 전제 조건과 실시간 점검을 통과할 때까지 실험적입니다.
- 그 밖에 언급된 서비스에는 조직이 제공하는 호환 MCP 서버가 필요합니다. BugIt은 설정 안내를 제공하지만 그 서버를 함께 제공하거나 검증하지는 않습니다.

## 첫 리포트 작성

- 문제가 어디서, 얼마나 자주 발생하는지를 포함해 평이한 언어로 설명합니다.
- 재현 단계를 완성하는 데 필요한 질문에 답합니다.
- 미리 보기를 검토하되, 특히 비공개 데이터, 심각도, 프로젝트, 첨부 파일을 확인합니다.
- 정확히 `FILE IT`이라고 답하기 전에는 추적 시스템에 아무것도 등록되지 않습니다. "네"나 "진행해"는 확인이 아닙니다.

## 도움 받기

먼저 BugIt 에이전트에서 `Check status` 또는 `Check readiness`를 실행하세요. 문제가 계속되면 BugIt 계정 대시보드에서 지원 티켓을 열되, 비밀 정보나 기밀 프로젝트 자료를 포함하지 마세요. 지원은 영어로만 제공됩니다.
