# BugItを使い始める

> **翻訳に関するご注意。** 本書は機械翻訳であり、ネイティブスピーカーによる校閲を経ていません。正文は英語版です。相違がある場合は英語版が優先されます。最も正確で最新の記述については、英語版の文書をご参照ください。

BugItは、大まかなテストメモをVS Code内でレビュー済みのバグレポートへと変換します。VS CodeとGitHub Copilotを備えたWindows 11が、リリース認定済みのクライアント環境です。

## 始める前に

- 最新のVS Codeをインストールし、GitHub Copilotにサインインします。
- リリース認定済みのPython 3.10から3.14のインタープリターをインストールします。
- アカウントダッシュボードからBugItをダウンロードし、ローカルフォルダーに解凍します。
- トークン、顧客データ、非公開のソースコードは、チャットや設定ファイルに含めないようにします。

## 有効化と設定

- 解凍したBugItフォルダーを、信頼済みのVS Codeワークスペースとして開きます。
- Copilot ChatでBugIt QAエージェントを選択し、`Activate`と入力します（アカウントに両方がある場合は`--solo`または`--team`を付けます）。
- BugItがブラウザでBugItポータルを開きます。ご自身のBugItアカウントでサインインしてください。パスワードはブラウザ内にとどまり、VS Codeに入力されることはありません。
- このマシンで使うSoloまたはTeamの権利を選び、このデバイスを確認して承認します。
- VS Codeに戻ります。BugItが自動的に認証を完了します。コピー・貼り付け・表示するライセンスキーはありません。
- `Begin setup`と入力し、チームが利用する連携のみを選択します。
- トラッカーを一度だけ接続します： `python tools/connect.py jira`（`ado`、`github`、`gitlab`、`linear`、`clickup`、`asana`、`trello`、`shortcut`、`youtrack`、`bugzilla` も同様）。トークンはお客様自身のアカウントで作成し、マスクされたローカル入力欄に貼り付けます。保存先は OS の資格情報ストアで、ディスク上で読めることはありません。Windows ではあなたのアカウントだけが開ける暗号化された記録となり、macOS と Linux ではキーチェーンまたは libsecret に保管されます。
- チケットを起票する前に、選択したサービスとプロジェクトをBugItに検証させます。

## アクセスの管理

- 1つのインストールでは、同時に有効な権利は1つだけです。このマシンを別のSoloまたはTeamの権利に切り替えるには、`Switch license`と入力し、ブラウザで再度承認します。キャンセルした場合は現在の権利がそのまま維持されます。
- `Deactivate`はこのマシンからのみ権利を削除します。シート、デバイス、メンバーシップ、ロール、請求はVS Codeではなくポータルで管理します。
- Teamのアクセスは個人単位です。各メンバーは自分のBugItアカウントと有効なメンバーシップでサインインします。共有キーや共有ログインはありません。
- オンライン確認に成功すると、BugItはSoloでもTeamでも最大72時間オフラインで動作を続け、再接続するとすぐに最新のポータルの状態を適用します。
- 更新は署名済みの権利によって認証されるため、新しいビルドのダウンロードでキーを求められることはありません。

## 接続状態

- BugIt は 11 のトラッカーに、それぞれの REST API 経由で、お客様がご自身のアカウントで作成した資格情報を使って起票します： Jira Cloud、Azure DevOps、GitHub Issues、GitLab Issues、Bugzilla、YouTrack、Linear、Shortcut、ClickUp、Asana、Trello。セットアップは、頼りにする前に接続を検証します。
- Confluence Cloud はナレッジソースとして、ガイド付きの Atlassian Rovo MCP 経路（ブラウザーでサインイン）で接続します。Sentry と Notion は、前提条件とライブチェックに通るまで実験的機能です。
- 他の記載サービスには、組織が提供する互換 MCP サーバーが必要です。BugIt はセットアップの手引きを示しますが、それらのサーバーの提供や検証は行いません。

## 最初のレポート

- 問題を平易な言葉で説明し、発生した場所と頻度を含めます。
- 再現手順を完全なものにするために必要な質問に回答します。
- プレビューを確認します。特に非公開データ、重大度、プロジェクト、添付ファイルに注意してください。
- `FILE IT` とだけ返信するまで、チケットは登録されません。「はい」や《お願いします》は確認になりません。

## サポートを受ける

まずBugItエージェント内で`Check status`または`Check readiness`を実行してください。それでも問題が解決しない場合は、BugItアカウントダッシュボードからサポートチケットを起票してください。その際、機密情報や秘匿すべきプロジェクト資料は含めないでください。 サポートは英語のみで提供されます。
