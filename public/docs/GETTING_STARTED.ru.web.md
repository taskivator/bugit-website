# Начало работы с BugIt

> **Примечание о переводе.** Этот документ переведён машинным способом и не проверялся носителями языка. Определяющей является английская версия: при расхождениях преимущественную силу имеет английский текст. За наиболее точной и актуальной формулировкой обращайтесь к документу на английском языке.

BugIt превращает черновые заметки о тестировании в проверенные отчёты об ошибках прямо в VS Code. Windows 11 с VS Code и GitHub Copilot — это клиентская конфигурация, для которой сертифицирован выпуск.

## Перед началом

- Установите последнюю версию VS Code и войдите в GitHub Copilot.
- Установите сертифицированный для выпуска интерпретатор Python 3.10–3.13.
- Загрузите BugIt из личного кабинета своей учётной записи и распакуйте его в локальную папку.
- Не помещайте токены, данные клиентов и закрытый исходный код в чат и файлы конфигурации.

## Активация и настройка

- Откройте распакованную папку BugIt как доверенное рабочее пространство VS Code.
- В Copilot Chat выберите BugIt QA Agent и введите `Activate` (добавьте `--solo` или `--team`, если в вашей учётной записи есть оба).
- BugIt открывает BugIt Portal в браузере. Войдите под своей учётной записью BugIt: пароль остаётся в браузере и никогда не вводится в VS Code.
- Выберите право Solo или Team для этой машины, затем проверьте и подтвердите это устройство.
- Вернитесь в VS Code. BugIt завершает авторизацию автоматически: нет никакого лицензионного ключа, который нужно копировать, вставлять или показывать.
- Введите `Begin setup` и выберите только те интеграции, которые использует ваша команда.
- Позвольте BugIt проверить выбранный сервис и проект перед созданием тикета.

## Управление доступом

- В одной установке одновременно используется только одно активное право. Чтобы перевести эту машину на другое право Solo или Team, введите `Switch license` и снова подтвердите в браузере; если отменить, текущее право сохраняется.
- `Deactivate` удаляет право только с этой машины. Места, устройства, участия, роли и оплата управляются в Portal, а не в VS Code.
- Доступ Team индивидуален: каждый участник входит под своей учётной записью BugIt и с активным участием. Нет ни общего ключа, ни общего входа.
- После успешной онлайн-проверки BugIt продолжает работать офлайн до 72 часов — как для Solo, так и для Team — и применяет актуальное состояние Portal сразу после переподключения.
- Обновления авторизуются вашим подписанным правом, поэтому при загрузке новой версии ключ никогда не запрашивается.

## Состояние подключения

- BugIt заводит тикеты в одиннадцати трекерах через собственный REST API каждого, используя учётные данные, которые вы создаёте в собственном аккаунте: Jira Cloud, Azure DevOps, GitHub Issues, GitLab Issues, Bugzilla, YouTrack, Linear, Shortcut, ClickUp, Asana и Trello. Настройка проверяет подключение до того, как вы начнёте на него полагаться.
- Confluence Cloud подключается как база знаний по сопровождаемому пути Atlassian Rovo MCP со входом в браузере. Sentry и Notion остаются экспериментальными, пока не выполнены их предварительные условия и живые проверки.
- Другим названным сервисам нужен совместимый MCP-сервер, предоставленный организацией. BugIt даёт рекомендации по настройке, но не поставляет и не тестирует эти серверы.

## Ваш первый отчёт

- Опишите проблему простым языком, указав, где она произошла и как часто.
- Ответьте на любые вопросы, необходимые для того, чтобы шаги воспроизведения были полными.
- Проверьте предпросмотр, особенно закрытые данные, серьёзность, проект и вложения.
- Подтверждайте только тогда, когда место назначения и итоговый тикет верны.

## Получить помощь

Сначала выполните `Check status` или `Check readiness` в агенте BugIt. Если проблема сохраняется, создайте запрос в поддержку из личного кабинета своей учётной записи BugIt, не включая в него секреты и конфиденциальные материалы проекта. Поддержка предоставляется только на английском языке.
