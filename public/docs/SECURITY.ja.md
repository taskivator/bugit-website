# セキュリティ

> **翻訳に関するご注意。** 本書は機械翻訳であり、ネイティブスピーカーによる校閲を経ていません。正文は英語版です。相違がある場合は英語版が優先されます。最も正確で最新の記述については、英語版の文書をご参照ください。

BugIt QA Agent は、人が判断に関わる（human in the loop）アシスタントです。お使いの VS Code セッションと、有効にした連携機能を通じてのみ動作します。

## BugIt による保護のしくみ
- **確認なしの書き込みはありません。** レポートを含む作成、コメント、添付、通知はすべて事前にプレビューされます。取り消しできない登録には、FILE IT と入力していただく必要があります。チャットの文章だけで登録されることはなく、単なる「はい」では不十分です。例外が一つあります。`notify connect`、`notify test`、`notify doctor --live` でご自身が開始する接続テストは、プレビューなしで固定のテストメッセージを1通送信します。送信先は指定したチャネル、指定がない場合はオンにしているすべてのチャネルです。このメッセージにレポートの内容は含まれず、dry run ではブロックされます。
- **Dry run = 作業が行われるすべての場所で読み取り専用。** `QA_AGENT_DRY_RUN=1` を設定すると、BugIt はトラッカーへの書き込みも、トラッカーからの読み取りも行いません。チケット、コメント、添付、通知は一切発生せず、保存された認証情報のロックも解除されません。例外が一つあり、これはお客様のデータではなく BugIt 自体に関するものです。このインストールのライセンス認証や更新のために意図的に実行するコマンドは引き続き BugIt 自身のライセンスサーバーに接続し、`tools/update.py` は取得した署名済みリリースを引き続きインストールします。シェルにこの変数が常に設定されているマシンでも、セキュリティ修正を受け取れる必要があるためです。チャットで「dry run」と伝えると、アシスタントに実行を控えるよう求めることになります。これは役に立ちますが、同じ保証ではありません。コードが強制するモードを設定できるのは環境変数だけです。
- **ファイルに秘密情報を置きません。** `config.json` には組織と URL のみを保存し、トークンは OS の認証情報ストアに保管されます。バリデーターは秘密情報のように見えるものをすべて検出します。`redact.py` は、下書きからメールアドレス、トークン、IP アドレスを可能な限り取り除きます。
- **初期状態はオフです。** すべての連携機能は無効の状態で提供され、オプトインするまで何も接続せず、何も登録しません。
- **出力はデータとして扱います。** ページ、チケット、クラッシュのテキストはコマンドではなくデータとして扱われるため、埋め込まれた指示は検出されて表示されますが、実行されることはありません。

## 既知の制限
- 書き込みのブロックを強制するのはエージェントであり、OS ではありません。環境変数が確実に停止できるのは同梱の Python ヘルパーだけです。信頼できる実行環境で実行してください。
- エージェントは接続したものすべてにアクセスでき、認証情報の権限範囲 = 影響範囲です。**最小権限**のトークンを使用してください。
- ほとんどのトラッカーでは課題を完全に削除できないため、そこでの「元に戻す」は設計上限定されています。

## セキュリティ強化チェックリスト
1. トラッカーごとに、最小権限の専用サービスアカウントを使用してください。
2. トークンは OS のストアに保管し、`config.json` には決して貼り付けないでください。
3. セットアップ後に `python tools/validate_config.py` を実行し、漏えいや設定ミスを検出してください。
4. 使用する MCP サーバーだけを起動し、それ以外は停止してください。

## 脆弱性の報告
再現手順を添えて **support@bugit.dev** までメールでお知らせください。セキュリティに関する報告のために公開の issue を作成しないでください。
