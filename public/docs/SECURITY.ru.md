# Безопасность

> **Примечание о переводе.** Этот документ переведён машинным способом и не проверялся носителями языка. Определяющей является английская версия: при расхождениях преимущественную силу имеет английский текст. За наиболее точной и актуальной формулировкой обращайтесь к документу на английском языке.

BugIt QA Agent является помощником, в работе которого решения принимает человек (human in the loop). Он действует только через ваш сеанс VS Code и интеграции, которые вы включили.

## Как BugIt вас защищает
- **Никакой записи без подтверждения.** Каждое создание, комментарий, вложение или уведомление, которое содержит ваш отчёт, сначала показывается для предварительного просмотра; для необратимой отправки нужно ввести FILE IT. Один лишь текст в чате никогда ничего не отправляет, и простого «да» недостаточно. Одно исключение: проверка подключения, которую вы запускаете сами командой `notify connect`, `notify test` или `notify doctor --live`, отправляет одно фиксированное тестовое сообщение без предварительного просмотра: в канал, который вы укажете, или, если вы не укажете ни одного, во все включённые вами каналы. Оно не содержит ничего из отчётов, и режим dry run его блокирует.
- **Dry run = только чтение, везде, где идёт ваша работа.** `QA_AGENT_DRY_RUN=1` запрещает BugIt записывать в ваши трекеры и читать из них: ни тикетов, ни комментариев, ни вложений, ни уведомлений, и никакие сохранённые учётные данные не разблокируются. Одно исключение, и оно касается самого BugIt, а не ваших данных: команды, которые вы намеренно запускаете для лицензирования или обновления этой установки, по-прежнему обращаются к собственному серверу лицензий BugIt, а `tools/update.py` по-прежнему устанавливает загруженный им подписанный выпуск, потому что компьютер, в оболочке которого эта переменная задана постоянно, всё равно должен иметь возможность получить исправление безопасности. Фраза «dry run» в чате просит помощника повременить; это полезно, но не даёт той же гарантии: только переменная окружения задаёт режим, который обеспечивает код.
- **Никаких секретов в файлах.** `config.json` содержит только организации и URL-адреса; токены хранятся в хранилище учётных данных вашей ОС. Валидатор помечает всё, что похоже на секрет. `redact.py` по мере возможности удаляет из черновиков адреса электронной почты, токены и IP-адреса.
- **По умолчанию выключено.** Все интеграции поставляются отключёнными; ничего не подключается и ничего не отправляется, пока вы сами этого не включите.
- **Вывод является данными.** Текст страниц, тикетов и сбоев обрабатывается как данные, а не как команды, поэтому внедрённые инструкции помечаются и показываются, но не выполняются.

## Известные ограничения
- Блокировку записи обеспечивает агент, а не операционная система; переменная окружения жёстко останавливает только входящие в комплект вспомогательные программы на Python. Запускайте его в доверенной среде выполнения.
- Агент получает доступ ко всему, что вы подключаете, и объём прав учётных данных = масштаб возможного ущерба. Используйте токены с **минимальными привилегиями**.
- Большинство трекеров не умеют по-настоящему удалять задачу, поэтому «отмена» там ограничена намеренно.

## Контрольный список для усиления защиты
1. Используйте для каждого трекера отдельную служебную учётную запись с минимальными привилегиями.
2. Храните токены в хранилище ОС; никогда не вставляйте их в `config.json`.
3. После настройки запустите `python tools/validate_config.py`, чтобы выявить утечки и ошибки конфигурации.
4. Запускайте только те MCP-серверы, которыми пользуетесь; остальные останавливайте.

## Как сообщить об уязвимости
Напишите на **support@bugit.dev** и опишите шаги для воспроизведения. Не создавайте публичную задачу для сообщений о безопасности.
