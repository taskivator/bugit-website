# 安全

BugIt QA Agent 是一个由人来做决定的助手（human in the loop）。它只通过你的 VS Code 会话和你启用的集成来执行操作。

## BugIt 如何保护你
- **未经确认，不做任何写入。** 每一次包含你报告内容的创建、评论、附件或通知都会先预览；不可撤销的提交需要你输入 FILE IT。仅凭聊天文字永远不会提交，简单的「好」也不够。有一个例外：你自己用 `notify connect`、`notify test` 或 `notify doctor --live` 发起的连接测试，会在不预览的情况下发送一条固定的测试消息，发送到你指定的频道；如果你没有指定，则发送到你已开启的每个频道。这条消息不包含任何报告内容，并且 dry run 会阻止它。
- **Dry run = 只读，覆盖你工作的每一个地方。** `QA_AGENT_DRY_RUN=1` 会阻止 BugIt 写入你的缺陷跟踪系统，也会阻止它从中读取：不会产生工单、评论、附件或通知，也不会解锁任何已保存的凭据。有一个例外，它关乎 BugIt 本身，而不是你的数据：你为授权或更新此安装而特意运行的命令仍会连接 BugIt 自己的许可证服务器，`tools/update.py` 仍会安装它获取的已签名版本，因为 shell 中长期带有此变量的机器仍必须能够接收安全修复。在聊天中说「dry run」是请助手暂缓操作，这很有用，但并不是同等的保证：只有环境变量才能设定代码强制执行的模式。
- **文件中不存放机密。** `config.json` 只保存组织和 URL；令牌保存在你操作系统的凭据存储中。验证器会标记任何看起来像机密的内容。`redact.py` 会尽力从草稿中清除电子邮件地址、令牌和 IP 地址。
- **默认关闭。** 每个集成在交付时都处于停用状态；在你选择启用之前，不会连接任何服务，也不会提交任何内容。
- **输出即数据。** 页面、工单和崩溃信息中的文本被视为数据而非命令，因此注入的指令会被标记并显示出来，而不会被执行。

## 已知限制
- 写入拦截由代理强制执行，而不是由操作系统强制执行；环境变量只会强制停止随附的 Python 辅助工具。请在可信的运行环境中运行它。
- 代理可以访问你连接的一切，凭据的权限范围 = 可能造成的影响范围。请使用**最小权限**的令牌。
- 大多数缺陷跟踪系统无法真正删除问题，因此在这些系统中，「撤销」按设计是受限的。

## 安全加固清单
1. 为每个缺陷跟踪系统使用专用的、最小权限的服务账号。
2. 将令牌保存在操作系统的存储中；切勿将它们粘贴到 `config.json`。
3. 设置完成后运行 `python tools/validate_config.py`，以发现泄露和错误配置。
4. 只启动你使用的 MCP 服务器；停止其余的服务器。
